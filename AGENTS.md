# AGENTS.md

## What it is

The website of BareKeep (`https://barekeep.com`): static pages in nine languages, generated by Python (standard
library only) from `i18n/*.json` and `changelog.json`, committed in `public/` and served by Cloudflare Workers
static assets. No framework, no Node dependency, no analytics.

## Sources of truth

- Page list, copy sources, facts and translation rules: [docs/content.md](docs/content.md). Visual design:
  [docs/design.md](docs/design.md). Decisions: [docs/adr/](docs/adr/README.md). Contracts with the app (changelog
  format, addresses, download feed): [docs/contracts.md](docs/contracts.md).
- Legal and product facts originate in the product's own (unpublished) facts list; this repository mirrors the
  numbers in the Facts table of `docs/content.md`, which `scripts/check_facts.py` enforces.
- Docs win over code: if they disagree, fix the docs first and say so in the PR.
- English (`i18n/en.json`) is the reference for every translation.

## Directory boundaries

```
i18n/            languages.json and <code>.json: all copy, English is the reference
changelog.json   release history, written by the app's release flow
public/          the site: pages, lang.js, sitemap.xml, robots.txt are generated; style.css, download.js,
                 _headers, icon.svg, og.png are written by hand
scripts/build.py          site settings and the home page
scripts/check_facts.py    facts in the copy against the Facts table in docs/content.md
scripts/sitekit/          vendored sitekit (generator, checks, preview); never edited here
docs/            content, design, contracts, adr/
wrangler.jsonc   Workers static assets config
```

The generated files in `public/` (all `.html`, `lang.js`, `sitemap.xml`, `robots.txt`) are never edited by hand:
change the source and rebuild.

## Commands

```bash
python3 scripts/sitekit/check_i18n.py   # after editing i18n/*.json
python3 scripts/build.py                # regenerate public/; commit it with the source change
python3 scripts/sitekit/check_site.py   # pages, links, anchors, Content-Security-Policy
python3 scripts/check_facts.py          # facts across languages
python3 scripts/sitekit/preview.py      # local preview on http://localhost:8765/
```

After committing, `git diff --exit-code public/` must be clean. CI (`.github/workflows/ci.yml`) runs the same checks; `pr-title.yml` checks the PR title.

## Project rules

- Copy changes go to all nine languages in the same PR, with identical JSON formatting (2-space indent, UTF-8,
  trailing newline); no em or en dashes. Non-English legal pages and the FAQ keep the translation notice.
- A number in legal text is a fact: change the Facts table in
  [docs/content.md](docs/content.md) and the copy together.
- One address per page: no `_redirects`, no alias pages, no tracking, no cookies, no third-party scripts.
- Keep the paths the app links to stable (`/`, `/privacy`, `/terms`, `/refund`, `/changelog`, `/#pricing`).
- Do not edit `scripts/sitekit/`; a change it needs is made in sitekit and re-vendored.
- The CSP in `public/_headers` allows no inline styles and no external resources; its only `connect-src` is
  `dl.barekeep.com`.

## Commits and pull requests

Conventional Commits for commit messages and PR titles: `feat|fix|docs|refactor|perf|test|build|ci|chore|revert(scope)!: subject`
(scopes in `docs/contracts.md`). Branch `<type>/<issue>-<slug>`. The maintainer squash-merges. Do not commit or push
unless asked. Update `CHANGELOG.md` under `## [Unreleased]` for user-visible changes.

## Issues and pull requests

`gh issue create` and `gh pr create --body` skip the issue forms and the pull request template, so write their
structure yourself. Search open issues first; one issue is one problem.

- Issue title: one short sentence that says the problem or the outcome, in English or Simplified Chinese. No type
  prefix such as `[feat]`; the label carries the type.
- Bug, `--label bug`: `## What happened`, `## What you expected`, `## Steps to reproduce`,
  `## Version and environment` (browser, operating system, page address and language).
- Feature or improvement, `--label enhancement`: `## Problem`, `## Proposed solution`,
  `## Alternatives considered` (when there were any), `## Done when`.
- Documentation, `--label documentation`: `## Where`, `## What is missing, unclear or wrong`, `## Suggested change`.
- Labels: `accessibility` marks screen-reader, keyboard and contrast work, together with `enhancement` or `bug`.
- Pull request: the title is the Conventional Commits subject (it becomes the squash commit). The body has
  `## Summary` (what changes and why), `## Related issue` (`Closes #<n>`), `## How tested` (the commands run and
  their results, and what was not run) and `## Checklist`:
  `- [ ] PR title follows Conventional Commits`, `- [ ] Tests pass`,
  `- [ ] Documentation updated where behavior changed`, ticked only when true. Screenshots go into the body, not
  into the repository.

## Red lines

- Credentials never appear in PRs, issues, logs, reports or chat.
- Releases, signing and anything sent to an external service need the maintainer's confirmation. Deploys happen
  only from `main` through Cloudflare Workers Builds.
- Review `git status` and stage specific files; no blind `git add -A` of unknown files.
