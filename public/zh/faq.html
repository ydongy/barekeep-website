常见问题

没找到答案？BareKeep 会在运行日志和镜像的状态卡里用人话说明失败原因，先打开对应的镜像看看。

基础

BareKeep 是什么？

一个 macOS 菜单栏应用：把 GitHub、GitLab、Gitea、Forgejo 上的仓库持续镜像到你的 Mac，还能推送到你自己的 Git 服务器，做异地备份。每个镜像都是完整的 Git 仓库，随时可以克隆。

需要什么？

一台 macOS 26.0 或更高版本的 Mac，以及 Git。BareKeep 使用 macOS 自带的 Git；如果缺少「命令行开发者工具」，BareKeep 会显示引导页帮你安装（约 1 GB，来自 Apple）。缺少 Git 期间，已有镜像和设置不受影响，装好后自动恢复同步。

BareKeep 需要付费吗？

BareKeep 有免费版，最多管理 3 个镜像；还有 Pro，一次买断（不是订阅），没有这个限制。一个 Pro 授权码覆盖 1.x 的所有版本。详见价格。

可以在多台 Mac 上使用 BareKeep 吗？

可以。免费版可用于你拥有或控制的每一台 Mac。一个 Pro 授权码可以同时在你的 2 台 Mac 上激活；要换到另一台，请先在其中一台的“设置 › 许可”里取消激活。

可以退款吗？

可以，购买 Pro 后 14 天内，不需要说明理由。规则见退款政策。

授权码失效后，我的镜像会怎样？

已经镜像或备份的内容都不会被删除，磁盘上的镜像仍然可以读取。BareKeep 回到免费版：前 3 个镜像继续同步，其余的保持原样但不再同步，直到你升级。

BareKeep 会改动我在 GitHub 或 GitLab 上的仓库吗？

不会。数据只按 来源、本机、备份 的方向流动，BareKeep 从不推送到来源。

支持哪些 Git 平台？

GitHub、GitLab、Gitea、Forgejo（含 codeberg.org）、后三者的自建实例，以及任意 https Git 地址。自建实例先在 设置 › 平台 里添加，之后既可以作来源，也可以作备份目标。

如何获得帮助？

先看出问题的镜像的运行日志和状态卡片，它们会用平实的话解释失败原因。如果还是没解决，请发邮件到 support@barekeep.com，并说明状态卡片显示的内容。请不要发送访问令牌。

同步与备份

同步是怎么运行的？

「立即同步」马上运行一个镜像；计划同步按计划自动运行。失败的运行会退避重试，运行记录和每次运行的输出都在镜像详情页。「暂停同步」会停止自动运行，仍可手动同步。

备份是怎么工作的？

添加一个或多个备份目标（Gitea、Forgejo、GitLab 或 GitHub），每个镜像可选择推送到哪些。平台有接口时，BareKeep 会自动建私有库。备份是可选的：不设置时，镜像只保存在本机。

「内容分歧」是什么意思？

备份上有本机镜像没有的提交，比如来源被强制推送之后。为避免覆盖它们，BareKeep 不会推送，并暂停这个镜像的自动同步。请检查备份，或选择以来源为准覆盖…，把备份的分支与标签重置为与来源一致。仅存在于备份中的提交将不再被引用，如需保留，请先拷贝本地目录。

隐私与安全

访问令牌存在哪里？

只存在 Mac 的钥匙串里，每个来源、每个备份目标各一条。不写入文件、不进日志、不出现在命令行或环境变量里，经管道交给 git。

BareKeep 会收集数据吗？

没有遥测，没有崩溃报告，没有账号。BareKeep 发送的数据只有更新检查；如果你购买 Pro，还有你的授权码和设备标签，发给支付服务商。隐私政策列出了 BareKeep 连接的每一个地址。

BareKeep 怎么更新？

BareKeep 每天检查一次新版本，你主动要求时也会检查（可在设置里关闭每日检查），你确认后在应用内安装。两种方案的更新均免费。每个版本的更新内容见更新日志。
